Page 1 — High-level system design

Everything owns one job.

MockX is assembled from a small set of intentionally narrow components, each with a single responsibility. The lifecycle coordinator serializes all state transitions. The scheduler maintains simulated time. The engine owns the books and matching. The gateway bridges FIX to the internal domain, while the optional ITCH publisher consumes the engine's authoritative displayed-order stream. The optional GLIMPSE service captures recovery snapshots at the same sequence boundary.

1.1

1.2

Exchange lifecycle

The exchange has six explicit states. Every state mutation is serialized through one asyncio.Lock in ExchangeLifecycle. Click each state to see its behavior.

STOPPED Initial / after end
STARTING Resetting run state
ACTIVE Accepting traffic
RUN_FAILED Metrics lost; rerun required
ENDING Flushing & finalizing
FAILED Unrecoverable error

STOPPED

No simulation session is active. Administrative start is available. FIX application ingress and time advancement are rejected. Retained due FIX reports can still be attempted immediately on reconnect, without advancing the clock.

Session start flow

Flush inactive metrics → close WebSockets → reset engine/scheduler/RNG → allocate the next generation and install fresh identifiers/sequences → reschedule retained FIX deliveries → admit initial book metrics → start a fresh ITCH/Mold session and enable its GLIMPSE snapshot generation when configured → publish ACTIVE.

A failure before destructive reset restores STOPPED. After reset, metric admission loss creates an endable RUN_FAILED generation, including when an initial snapshot is rejected before the feed starts. Other startup failure after reset enters restart-required FAILED. Market-data runtime failure alone does not fail an otherwise healthy run; degraded ITCH also revokes GLIMPSE access to that generation.

Session end flow

Flush accepted metrics → revoke the ending GLIMPSE generation → publish end markers and Mold end-of-session for a coherent ITCH feed → capture current-run final statistics → close the run to STOPPED. A failed flush keeps the run open in ACTIVE or RUN_FAILED for retry. Ending an already stopped run is idempotent.

Session end retains undelivered FIX records. STOPPED does not advance the clock automatically, but reconnect can immediately attempt due backlog. The next start reschedules retained records across generations.

Publishing STARTING or ENDING accepts the transition. Its owned task keeps the lifecycle lock until completion, even if the caller is canceled repeatedly; cancellation propagates afterward. Cancellation before acceptance does not start a transition or cancel pending final broadcasts. Internally interrupted writes retain their records for retry. Lifecycle states and transitions: lifecycle.py. Scheduler state is a separate SchedulerState contract. Gating logic: ingress rejected with Business Message Reject (35=j) during STARTING/ENDING/STOPPED/RUN_FAILED/FAILED.
1.3

Two clocks, one purpose each

MockX strictly separates simulated time (the domain clock that determines event ordering, fill timestamps, and report scheduling) from monotonic real time (used to measure computation duration and govern persistence recovery waits). Persistence retry deadlines do not advance or rewind simulated time.

Simulated clock

A datetime stored on LatencyScheduler.current_time. Advanced explicitly by advance_time() or run_until() in external mode, or by a background asyncio task in realtime mode. All order timestamps, fill timestamps, report timestamps, and event scheduling use this clock. Never calls sleep().

latency.py — LatencyScheduler.current_time, advance_time(), run_until()

Monotonic clock

Backed by time.perf_counter_ns() via PerfCounterClock. Used for real CPU duration measurements: match loop, book commit, engine command, report creation, and FIX serialization. Exposed as microsecond Prometheus histograms (e.g. mockx_match_loop_duration_us). Persistence uses time.monotonic_ns() for retry deadlines and buffered-record age. Startup health-check and explicit-flush failures also defer automatic recovery. Writes clear retry state on success; healthy probes clear it only with an empty buffer. Session end and shutdown's final drain bypass automatic backoff while retaining their existing timeouts. Never influences event ordering or simulated timestamps.

latency.py — PerfCounterClock, monotonic_duration_ns(); metrics.py — BufferedMetricsWriter

external mode

Nothing advances time automatically. A test harness or admin endpoint calls run_until() / advance_time() explicitly. An entire trading day replays faster than reading this sentence. Events exactly at the advancement target are processed (inclusive).

realtime mode

A background task wakes every scheduler.interval_ms and calls run_until(current + interval_ms) while ACTIVE or RUN_FAILED. A failed run can still deliver reports and process feed activity; further trading is blocked. Manual advancement returns HTTP 409 CLOCK_MODE_CONFLICT.

1.4

FIX ingress: from wire to scheduler

QuickFIX callbacks for New Order Single (35=D), Order Cancel Request (35=F), and Order Cancel/Replace Request (35=G) parse immutable normalized command data only — they never touch the engine. A central run-scoped ingress sequencer timestamps and acknowledges each command, then drains envelopes in a deterministic four-key order.

1
QuickFIX callback fires → ParsedFixCommand is built. MsgType and MsgSeqNum are read from the header; order fields include ClOrdID, Symbol, Side, OrderQty, OrdType, Price, TimeInForce, and OrigClOrdID as applicable. gateway.py FIXApplication.fromApp()
2
Normalization → OrderNormalizer converts decimal strings to integer ticks/lots by exact divisibility, independently of ambient decimal context. Rejects OFF_TICK_PRICE, OFF_LOT_QUANTITY, PRICE_NOT_ALLOWED, and unsupported types; positive unit counts must fit signed 64-bit bounds. Produces immutable command data. validation.py, instruments.py
3
Ingress sequencer assigns run-local ingress_sequence, simulated_receive_timestamp, and run_generation. The envelope's ordering_key is:
(simulated_receive_timestamp, SessionID, MsgSeqNum, ingress_sequence)
4
Sorted drain → Envelopes are consumed in ascending ordering_key order. New orders become new_order_received scheduler events; cancels become cancel_received events; replacements become replace_received events. gateway.py — FIXApplication.drain_ingress_locked()
5
Scheduler FIFO preserves causal ordering among later equal-time stages. The ingress sequence is the final tie-break, never the sole FIFO source. It resets to zero when a fresh run generation is installed.

Why four keys?

Two commands from the same session with the same receive timestamp and different MsgSeqNum values keep their wire order. Different sessions share the order book but have no common wire sequence. Stable SessionID ordering makes their cross-session priority and interactions reproducible.

Ingress barrier

In-process harnesses driving the scheduler directly after FIX submission must await fix_app.wait_for_ingress() before advancing time. The returned IngressBarrier identifies the run generation and captured high-water sequence. Administrative and realtime advancement capture and await this barrier automatically, then drain its commands under the lifecycle lock before moving time.

FixIngressEnvelope and IngressBarrier: models.py. Sorted drain: gateway.py.

Exact numeric boundaries and serialization

Instrument scale is derived from the exact increment, ignoring trailing zeros. Explicit and inferred display precision both stay within 0-18 places and cannot conceal low-order increment digits. Grid validation, ITCH Price(4) conversion, exact products and statistics totals do not depend on the caller's decimal context.

Instrument display fields use fixed-scale decimal strings. Displayed average prices, including FIX AvgPx, round once from the exact integer notional-to-quantity ratio at configured price precision using round-half-even. Internal order/report average properties retain derived Decimal values in a fixed 28-significant-digit, round-half-even context; these values may be approximate and are not used to format wire averages.

Persisted book midpoints use configured price precision; the HTML UI keeps its unrounded midpoint, including a half-tick extra digit. No public fields, validation codes or configuration options change.

1.5

Run generation and public identifiers

Session start allocates the next run generation after destructive reset, before admitting initial book metrics. An initial admission failure consumes that generation and leaves an endable RUN_FAILED run. All public identifiers embed this generation, making it impossible to confuse a trade from run 3 with a trade from run 7.

Numeric engine handles remain internal to REST, FIX, and WebSocket contracts. Within one generation-qualified Mold session, ITCH allocates a separate run-local displayed Order Reference Number on each placement and uses trade ID as Match Number. FIX/internal OrderID stays stable through replacement; a removed displayed reference is never reused. GLIMPSE captures the current references and ITCH sequence atomically. The cancel-reject domain ID is an application identity for deduplication and observability — FIX OrderCancelReject (35=9) has no ExecID, so the domain ID is not serialized on the wire.

RunIdentifierScope: identifiers.py. MatchingEngine.identifier_scope: engine.py. Readme section: "Public exchange identifiers include the allocated simulation-run generation."
1.6

API surface comparison

MockX exposes five distinct interfaces, each with a different contract.

FIX 4.4

Native order entry

The only public order-entry interface: New Order Single (35=D), Order Cancel Request (35=F), and Order Cancel/Replace Request (35=G). Execution Reports (35=8) and Order Cancel Rejects (35=9) are delivered asynchronously through the reliable application delivery queue. Replace accepts live GTC limit price/total-quantity amendments, acknowledges with ExecType=5, and rejects with CxlRejResponseTo=2. No interim Pending Replace report is emitted. Market Data Request (35=V) is rejected. Book data is available through REST/WebSocket and the optional ITCH/GLIMPSE feeds.

REST

Administration & inspection

GET /book/{symbol} for immutable snapshots. POST /api/v1/session/start and /end for simulation control. POST /admin/advance-time for clock advancement. GET /stats and /metrics for observability. REST exposes no order-entry route; orders, cancellations, and replacements use FIX.

WebSocket

Streaming market data

Connect to /ws/{symbol}. First message is the current immutable snapshot. Every committed matching action publishes one market_data message with incremental trades. Heartbeats are distinct. Global per-exchange sequence incremented per publication.

ITCH 5.0

Displayed-order multicast

Optional downstream-only MoldUDP64 feed. Publishes A, one passive-side E/C per fill, D, and priority-preserving replacement reductions as X, plus session/directory/trading-state messages. Reprioritization emits old-reference D, passive E/C for any fills, and fresh-reference A for a resting remainder. One internal lot is one ITCH share. No retransmission service is provided.

GLIMPSE 5.0

Atomic snapshot recovery

Optional SoupBinTCP service. Sequence-1 logins receive R, current H with trading state T, every live resting order as A, and final G with the Mold next-message sequence. Fresh snapshots are allowed in ACTIVE or RUN_FAILED with a healthy scheduler and coherent current-generation ITCH feed. Interrupted spins are replayable within strict TTL/session/byte bounds.
