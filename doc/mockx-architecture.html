Architecture

MockX owns one deterministic engine and one lifecycle serialization boundary per venue. FIX, ITCH, GLIMPSE and QuestDB are required. External clients include strategy/replay FIX sessions, native feed consumers and a journal-driven Grafana projector.

Ownership and identities

SessionID scopes client identifier claims. Participant identity controls ownership and self-trade prevention; alias determines immutable liquidity classification. Each run has a UUID, separate scenario label and deterministic engine generation. Logical FIX order identity survives replacements; displayed references change when priority is lost. Feed session names are fresh across restarts.

Committed effects

Matching stays synchronous. Reports, trades and ordered displayed-book changes are collected privately, then published after the command passes invariant checks. Both QuestDB and ITCH consume the same native book effects. Full-book construction is reserved for coherent captures and REST diagnostics. Prometheus receives operational counters, CPU histograms and batch-refreshed gauges.

Persistence and snapshots

The bounded writer admits complete command groups, combines consecutive groups in transactional one-table HTTP writes, counts queued and in-flight rows/bytes, and preserves identities on retries. Checkpoint captures preserve FIFO, logical/displayed identities, leaves, ticks, side and category. GLIMPSE and checkpoint encoding share this protocol-neutral capture. Checkpoint completion markers carry expected count and journal/ITCH cuts; incomplete captures are ignored.

Failure boundary

Request rejection is isolated. Validated fills remain truthful if journal admission fails; later trading stops. Pressure timeout retains admitted rows. Required publisher/listener failures invalidate GLIMPSE and fail the run after current reporting. Client disconnects and receiver UDP gaps are isolated. Unexpected engine failure stops scheduling with no fabricated command-complete marker. There is no rollback or restart restoration.
