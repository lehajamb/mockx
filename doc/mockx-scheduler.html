Scheduler

The scheduler uses a heap ordered by timestamp and a monotonically allocated sequence. Equal-time events remain FIFO; events at the advancement target execute. Matching itself is synchronous, so lifecycle requests cannot interrupt a partially processed engine command.

physical FIX ingress
  -> deterministic parent position
     -> list members in ListSeqNo order (ordinary new_order_received events)
        -> inbound network + configured session delay
           -> order_arrived / cancel_arrived / replace_arrived
              -> engine latency
                 -> synchronous order / cancel / replace processing
                    -> command effects admitted, ITCH deltas buffered, FIX reports queued
                       -> outbound latency -> individual report delivery

Cooperation and pressure

Default processing batches contain 128 events. Before clock changes, scheduler yields, persistence waits or captures, ITCH buffered messages are flushed. Between commands, 80% row or byte occupancy pauses producers until both reach 50% or below, with a 10-second deadline. Queued and in-flight rows both count. A single completed command may await admission; the event loop can run the writer and administrative diagnostics during cooperation.

Time control

External mode advances through POST /admin/advance-time; realtime mode uses configured wall-clock ticks to advance simulated time. Negative latency, naive timestamps and reversal are rejected. Event processing limits stop runaway self-rescheduling. Run reset clears scheduled business events while retaining generation-qualified delayed report delivery and its original UUID.

Failure and cancellation

Engine/invariant exceptions enter fail-stop with a dead-letter diagnostic and preserve the original cause. A fresh run resets the scheduler. Accepted lifecycle transitions and checkpoint/command settlement retain the lock until completion, including after caller cancellation. No retry of a partially executed engine command or fabricated completion is introduced.
